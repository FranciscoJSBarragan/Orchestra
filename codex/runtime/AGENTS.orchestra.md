## Orchestra routing

Keep the root responsible for specification alignment, tiering, capability routing, compact synthesis, the local plan, blockers, ordinary reversible in-scope decisions, phase commits, direct PR observation, and final judgment. Orchestra is an explicit planned-work route, not the default implementation route. Native Codex Plan Mode and Orchestra are mutually exclusive: never invoke Orchestra while Plan Mode is active, even when `$orchestra` is requested; tell the user to leave Plan Mode first. In normal chat, direct change, fix, implementation, and implementation of a prior native Codex plan remain direct work outside Orchestra. Start `$orchestra` only when the user explicitly requests Orchestra or asks to create, prepare, or write the implementation plan. Use `$orchestra-phase-commit` only after review and verification pass, then route delivery through `$orchestra-delivery-policy`. Use `${CODEX_HOME:-$HOME/.codex}` as the installed Codex root. For each dispatch, resolve `tiers.<tier>.<capability>` from `${CODEX_HOME:-$HOME/.codex}/orchestra/roles.toml`, load its `profile` from `${CODEX_HOME:-$HOME/.codex}/agents/`, and pass the entry's explicit `model` and `reasoning_effort`. Compose only the internal references named by `$orchestra`.

Reuse the preceding conversation, ask only genuine specification gaps, and confirm Objective, User-visible behavior, Constraints, Acceptance, Exclusions, Decisions, and Open questions before tiering. Use only standard or critical. Do not persist the provisional specification or an unapproved plan. After the root has reviewed the formal plan and the user approves execution, write the exact approved plan directly as `active` at `git rev-parse --git-path orchestra/plan.md`; only `active`, `blocked`, and `completed` are valid. Approval permits reviewed phase commits, not merge, delivery, deployment, or release. Profiles never write the plan. Keep transient packets and consecutive clean PR heads in memory or system temporary storage, reuse context deltas, return accepted findings to the same implementation owner, and resume local failures locally. The root invokes `commit_phase.py` and `pr.py observe` directly; neither is an agent capability. Read explicit repository policy and task direction before hold, PR, or local delivery. Opening a PR authorizes review/fix/commit/push until clean but never merge; merge requires separate authority. Never install or synchronize these managed sources during ordinary task execution.
